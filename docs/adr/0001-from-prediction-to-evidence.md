# ADR 0001：从「在线预测 + 建议制止损」转向「证据基础设施」

- 状态：已接受（本次收尾式改造；具体日期以提交历史为准）
- 基线：commit 5315865（2026-10-19），仓库 Anhao1314/RL-Sentinel
- 相关：RESTART.md（重启判据）、SECURITY.md（安全事件与防护）、CHANGELOG.md（版本回溯）

## 背景

【事实】仓库有两代目标：

- v1：面向 Go2W/MuJoCo RL 训练，预测最终水平 / 剩余时长 / 失败概率，并给出 R0–R3 建议制止损。
- v0.2（rl_risk_replay/ 与 research/）：目标已收窄为「忠实记录某 checkpoint 当时真正知道什么，
  产出可版本化、可校验的证据链」。

【事实】两代目标并存，且仓库缺少把它们区分开的治理层：

- 仓库曾换过 4 个名字：RL Sentinel / rl_risk_replay / 发行包名 rl-training-risk-replay
  （pyproject.toml）/ CLI 名 rl-risk。
- PROJECT_CONTEXT.md、AGENTS.md、PHASE_RECORD.md、QUANT_PLAN.md 等 6 份顶层中文文档
  仍描述旧的在线止损目标。
- 此前没有 LICENSE / CHANGELOG / ADR / SECURITY / ROADMAP；0 tag、0 release、0 open issue，
  9 个 PR 全部合并或关闭；没有密钥扫描门禁，也没有安全事件记录。

【事实】数据与集成现状：

- 18 个 observed run（6 pass / 12 fail），12 个 fail 全部是 zero-S0 受控消融；48 个 legacy run。
- 只有 multi-segment 一个 trainer 接入 v0.2 事件流。
- 历史 CSV 无 available_at 字段，严格回放可用的历史运行数为 0。
- docs/RELIABILITY_V2.md:152-156 明写：没有收集新的多任务数据、没有证明跨任务早停效果、
  没有在远端训练集群上线；并记「没有真实算力节省结论」。

【事实】安全事件：git 历史中 config.json 曾明文提交飞书 webhook 完整 URL
（commit ff83740 引入，647fa89 删除）。当前 HEAD 已无该值，但仓库此前没有 SECURITY.md、
没有密钥扫描门禁、没有事件记录。该 webhook 已由所有者于 2026-11-05 确认在飞书侧轮换并
停用，历史 URL 不再有效（见 SECURITY.md）；但 git 历史中的明文值未被清除，仍可通过全历史
检出 / fork / 缓存 / CI 日志取回，本仓库不改写 git 历史（见 [ADR 0002](0002-no-git-history-rewrite.md)）。

【推断】一个以「产出可版本化、可校验的证据链」为目标的仓库，对自身的定位变更、四次改名、
范围收窄与安全事件却没有对应的决策记录、版本标记、事件记录与门禁——即项目自身 provenance
（来源与决策链）缺失。这是本次收尾式改造的直接动机之一：先让仓库能证明自己「何时、为何、
决定了什么」，再谈对训练实验做同样的事。

## 决策

【推断】必须明确：这不是原目标达成后的升级，而是一次**主动收窄**——主动降低承诺范围，
使目标与现有数据、集成能力对齐。

- 【推断】直接原因：样本结构与训练端集成不具备——12 个 fail 全是人工（受控）消融、单 trainer、
  无自然失败、无 available_at、严格回放可用的历史运行数为 0。在此条件下继续调 R0–R3 阈值，
  只会生产无法证伪的结论。
- 停止按原目标（在线预测 + 建议制止损）产品化投入。
- 把仓库定位收敛为「RL 实验时间正确性 / 证据链的最小参考实现」。
- v1 与描述旧在线止损目标的顶层文档标记 RETIRED（保留不删）。
- main 冻结，只接受安全修复、复现性修复、文档更正三类改动。
- 补齐治理文件（LICENSE / CHANGELOG / ADR / SECURITY / RESTART）与审计门禁、
  as-of 语义对齐、单一规则源（详见 CHANGELOG.md [Unreleased]）。
- 重新开始按原目标投入，须同时满足 RESTART.md 的 4 项判据；本 ADR 不单独定义解冻条件。

## 后果

### 正面
- 目标与数据能力对齐，不再产出无法证伪的算力节省 / 早停 / 失败概率结论。
- 单一、可版本化、可校验的 as-of 证据链成为清晰、可交付的产物。
- 治理层首次具备 provenance：治理文件 + 版本回溯标注 + 审计门禁 + 事件记录，
  使仓库能追溯自身的决策与来源（对应背景中的 provenance 缺失）。
- 冻结收敛维护面；v1 资产保留可回溯，不删除。
- 安全事件从「仅 git 历史可追」变为有治理层记录与门禁约束。

### 负面
- 不再回答「能节省多少算力 / 剩余时长 / 失败概率」这类原目标问题。
- 不再具备在线止损能力，R0–R3 建议不再作为产品能力演进。
- v1 资产（采集、因子、规则、回测、日报及 P0–P4 计划）退役，既有投入沉没。
- 6 份旧顶层文档与现状不一致，保留但可能误导读者（以 RETIRED 标记缓解，不删除）。
- 命名不一致的历史遗留（仓库名 / 包名 / CLI 名 / 文档口径）不在此次改造解决范围。
- 解冻门槛高（4 项判据须同时满足），短期内不会有跨任务早停效果结论。

## 备选方案

### 方案一：继续按原目标产品化
继续调阈值、补在线止损、做多任务早停。
否决：样本结构与训练端集成不具备（见「决策」），继续调阈值只会生产无法证伪的结论；
docs/RELIABILITY_V2.md:152-156 亦自陈未证明跨任务早停、未在远端训练集群上线。

### 方案二：彻底归档停更
archive 仓库、不再维护、不再补文档。
否决：当时存在未处置的安全事件与治理 provenance 缺失，
直接归档会把「无决策记录、无事件记录、无门禁」的状态固化；
且 v0.2 的 as-of 证据链仍是一个值得保留的最小参考实现。

### 方案三：转向证据基础设施（所选）
把定位收敛为时间正确性 / 证据链的最小参考实现，并补齐治理层与冻结规则。
理由：与现有能力一致（事件契约、append-only 存储、as-of 回放、SHA-256 证据包、
受控实验与未来扰动对抗、DuckDB 研究层均已具备），目标可证伪、可版本化、可校验，
且能顺带补齐项目自身 provenance。代价是主动放弃原目标（见「负面」）。

## 依据

- 【事实】两代目标、4 次改名、6 份旧文档、治理文件与 tag/release/PR 数量、
  18/6/12/48 运行数、单 trainer、无 available_at、严格回放可用历史为 0、
  RELIABILITY_V2 自陈、webhook 的 ff83740 / 647fa89 与当前 HEAD 状态：见「背景」逐条，
  来源为仓库文件与 git 历史（pyproject.toml、PHASE_RECORD.md、docs/RELIABILITY_V2.md、
  SECURITY.md、CHANGELOG.md）。
- 【推断】「主动收窄」「继续调阈值只会生产无法证伪的结论」「provenance 缺失是改造动机」
  以及各备选方案的否决判断，均为基于上述事实的工程判断，不是测量或验证结果。
- 【待确认】重启 4 项判据的满足情况（见 RESTART.md）。

## 边界：事实 / 推断 / 待确认

- 【事实】可由仓库文件、提交历史、git 对象核对的陈述：两代目标、4 次改名、6 份旧文档、
  治理文件与 tag/release/PR 数量、18/6/12/48 运行数、单 trainer、无 available_at、
  严格回放可用历史为 0、RELIABILITY_V2 自陈、webhook 的 ff83740 / 647fa89 与当前 HEAD 状态。
- 【推断】基于事实的解释、价值判断与因果判断：本次是「主动收窄」而非达成后升级、
  继续调阈值不可证伪、provenance 缺失构成改造动机、三选一的取舍理由。
- 【待确认】需所有者或外部系统核对后才能定论的事项：训练端是否仍产数据、
  是否存在内部使用方、CI 门禁实际接线状态。

是否正式废弃 v1 的 P0–P4 计划仍待所有者确认。
